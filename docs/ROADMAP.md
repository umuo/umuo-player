# 从 Spike 到首版

## 当前：可运行架构验证

- 独立 KMP 核心、Android 手机/平板与 TV 两入口。
- 三源最小连接、浏览、播放计划和会话上报路径。
- WebDAV 本地索引、电影/剧集、NFO、海报、人工纠错与续播。
- 可选 TMDB、只读来源、凭据安全边界。
- Apple 共享 framework 与 SwiftUI 验证壳。
- 合成服务、契约测试、设备证据和限制记录。

## 第一阶段：三端三协议可用版本

Emby/Jellyfin 目标已明确为完整观看客户端，能力矩阵与阶段验收见 [完整观看客户端](MEDIA_SERVER_CLIENT.md)。当前实现不等于完整功能交付。


1. 使用明确版本的真实 Emby/Jellyfin 与至少两种 WebDAV 实现验收；补齐服务器 DeviceProfile 条件、分卷、多版本、特殊代理与字幕协商。
2. 补齐自动匹配的语言/别名、剧集资料缓存、整目录删除回收、万级库扫描进度、完整重新认证体验和连接删除；来源编辑已实现。
3. 完成手机手势、横竖屏、平板多栏、全屏、PiP、TV 焦点恢复、遥控长按及系统媒体按键矩阵。
4. 在手机、Pad、TV 真机上验证 HEVC/HDR、复杂 ASS、AC3/EAC3、音频直通和高码率；据失败矩阵决定是否需要 mpv/libVLC。
5. 完成 TMDB logo/服务条款检查、传递依赖 SBOM、正式签名、无障碍、隐私说明和崩溃恢复。设备记录和访问凭据不进入公开产物。

## 第二阶段：Apple 应用

共享协议和索引保持不变，实现 Keychain、平台生命周期和 Apple 播放引擎；手机/平板与 TV 分别适配 SwiftUI。先对比 AVPlayer 与 VLC 的认证流、容器、字幕和系统集成，再选生产默认引擎。当前 Kotlin tvOS 为 Beta，升级需保留编译及运行回归。

## 第三阶段：生态扩展

有实际需要时增加 SMB、局域网发现、投屏、离线下载与更多元数据来源。自有账号、跨端同步和第三方动态插件需要独立安全与兼容设计，不提前引入服务端负担。
