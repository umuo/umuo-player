# WebDAV 扫描与请求压力

## 默认行为

扫描默认为单并发，收到上一次响应后至少等待 1 秒再发下一次请求；可在设置中改为 3 秒或 5 秒。认证握手、目录 PROPFIND、NFO 读取都经过同一限速器。主动启用 TMDB 时，本轮扫描的 TMDB 请求也使用同一限速器。

扫描只读目录和资料，不为了建立索引下载视频。普通媒体指纹未变化时复用已索引资料；tvshow.nfo 可能为剧集资料继承重新读取。取消或失败会保留未完成目录的队列，用户可手动恢复。

## 服务端拒绝请求

- 429 或 503：立即暂停整轮扫描，不连续自动重试。解析 Retry-After 的秒数或 HTTP 日期，至少冷却 60 秒，保存冷却截止时间；未到时间再次点击扫描不会发出请求。
- 最终认证失败或 403：停止本轮扫描并提示检查账号/访问权限。正常的 Basic/Digest 认证握手不误判为失败，握手请求也有间隔。
- 普通目录局部失败：保留原索引及未完成队列，不因为某个目录暂时打不开而删除已有内容。

## 速率边界

以上控制针对本次扫描，不限制用户浏览、播放、海报加载或其他设备发出的请求。扫描期间暂停自动视频提帧；设置中还可关闭“自动提取视频预览”，关闭后已有本机缓存仍可显示。提帧会读取额外 Range 数据，关闭可减少后台请求。

并发数低不等于请求速率低。即使限速，也不能保证站点不会触发风控；站点还可能按账号、IP、流量或时间窗口计费/限流。应用不通过换账号、代理或连续重试绕过限流。

## 实现与验证

复用当前 Ktor 的 [SendingRequest / onResponse 钩子](https://ktor.io/docs/client-custom-plugins.html)，未引入另一套网络依赖。按 [RFC 6585 的 429 语义](https://www.rfc-editor.org/rfc/rfc6585.html#section-4) 与 [Retry-After 约定](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after) 等待。核心测试覆盖认证握手间隔、响应延迟、取消、Retry-After、暂停与队列保留；真实站点的策略仍以站点规则为准。
